# Data Model: init.sh Syncs K8s Port from CONTAINER_PORT

## Entity: Container Port Configuration

The `CONTAINER_PORT` value in the app's `.env` file is the single source of truth for
the app's port across all generated Kubernetes resources.

### Source

| Field | File | Location | Values |
|-------|------|----------|--------|
| `CONTAINER_PORT` | `.env` | app root | Numeric TCP port (e.g. `8080`, `9000`); default `8080` |

Resolution precedence (existing merge logic): CLI `--container-port` > `.env` value >
built-in default `8080`.

### Derivation Rules

- Missing/empty `CONTAINER_PORT` in `.env` → falls back to default `8080`.
- Non-numeric or otherwise invalid values are not introduced by this feature; the
  existing merge flow governs.

## Port Field Mapping (derived from CONTAINER_PORT)

| Manifest | YAML Path | Target Field |
|----------|-----------|--------------|
| `k8s/svc.yaml` | `spec.ports[]` | `port` |
| `k8s/svc.yaml` | `spec.ports[]` | `targetPort` |
| `k8s/deploy.yaml` | `spec.template.spec.containers[].ports[]` | `containerPort` |
| `k8s/deploy.yaml` | `spec.template.spec.containers[].livenessProbe.httpGet` | `port` |
| `k8s/deploy.yaml` | `spec.template.spec.containers[].readinessProbe.httpGet` | `port` |
| `k8s/ingress.yaml` | `spec.rules[].http.paths[].backend.service.port` | `number` |

### Match Format (generated by templates)

- `svc.yaml`: `port:` and `targetPort:` on their own indented lines; compact `- port:`
  list style also supported.
- `deploy.yaml`: `- containerPort:` on its own indented line; probe `port:` on its own
  indented line.
- `ingress.yaml`: `number:` on its own indented line.

## Validation

- Update only replaces numeric port values (pattern `[[:space:]]*[0-9]*`); non-numeric
  values are left untouched.
- Sync is idempotent: replacing `9000` with `9000` yields identical content.
- Files that do not exist are skipped without error (FR-007).

## State Transitions

- `init.sh --build`/`--deploy` on an existing app → manifests updated in place → applied
  to cluster (init.sh) and/or processed by `build.sh --auto-deploy`.
- `init.sh` without `--build`/`--deploy` → no state change to manifests (FR-008).
- `build.sh` template step on existing manifests → ports updated in place alongside the
  existing image/IMAGE_TAG update.
